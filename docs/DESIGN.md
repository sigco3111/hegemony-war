# 패권의 시간 — 설계 문서

OpenFrontIO를 싱글플레이 중심으로 개선한 포크입니다. 서버 없이 GitHub Pages 정적 배포만으로 동작하며, 계정·네트워크·사운드 없이 한 판씩 쌓이는 맛을 목표로 합니다.

- 플레이: https://sigco3111.github.io/hegemony-war-pages/
- 원작: https://github.com/openfrontio/OpenFrontIO (AGPLv3, §7 저작자 표시 유지)

## 개선 1 — 로컬 기록실과 업적 이식

원작의 맵별 승리 메달과 전적은 계정 API 서버 기반이라 정적 배포에서는 동작하지 않습니다. 이를 기기(localStorage)로 이식했습니다.

- `src/client/LocalRecords.ts`: `hegemony.records.v1` 키에 게임 기록(최대 200건, 최신순)과 맵별 승리 난이도(메달)를 저장합니다.
- 치트 옵션(무한 골드/병력, 즉시 건설)을 켠 게임은 기록에는 남지만 메달과 챌린지는 인정하지 않습니다.
- 싱글 모달의 기록 패널에서 총판·승리·승률·정복 맵 수와 판별 내역을 확인할 수 있습니다.

## 개선 2 — 전황 대시보드

게임 중 왼쪽 사이드바의 바차트 버튼으로 여는 실시간 전황 화면입니다.

- `src/client/hud/layers/WarDashboard.ts`
- 국가별 영토 점유율 도넛 차트, 시간에 따른 점유율 추이 그래프(200ms 틱, 20틱마다 표본, 최대 600표본), 전쟁 연대기(공격·정복·동맹 체결/파기/만료·교역 중단, 최대 200건).
- SVG 렌더링은 lit의 `svg` 태그를 사용합니다(`html` 태그로 만들면 HTML 네임스페이스가 되어 렌더되지 않습니다).

### 기록 검증과 마이그레이션 (v1.1)

- 시나리오형 챌린지는 클리어한 게임이 해당 프리셋의 규칙을 실제로 만족했을 때만 인정되며, 통과한 클리어는 증거(challengeProofs)가 기록에 고정됩니다.
- 과거 버그로 잘못 부여된 챌린지의 정정은 증거 기반으로만 합니다. 증거가 있는 정상 클리어는 보존하고, 무효가 확실한 부여만 한 번 회수하며, 증거 부재만으로는 삭제하지 않습니다. 마이그레이션은 기기당 한 번 실행되고 멱등입니다.
- 증거 없는 업적 재지급은 하지 않습니다.

## 개선 4 — AI 외교 심화 (견제 외교)

한 국가가 지도를 지배하기 시작하면 다른 국가 AI가 결집해 견제합니다.

- 도주 선두 판정: FFA에서 1위의 점유 타일이 2위의 일정 배수 이상일 때 (보통 3배 / 어려움 2배 / 불지옥 1.5배). 쉬움 난이도의 국가는 조직하지 않습니다.
- 견제 연합 수락: 도주 선두의 병력이 자신의 2배를 넘으면, 평소라면 거절할 약체의 동맹 요청도 연합 파트너로 수락합니다.
- 초국경 연합 요청: 명백한 열세(선두 병력의 절반 미만)일 때 국경을 공유하지 않는 위협받는 국가에게도 동맹을 제안합니다 (공격 틱마다 1/20 확률 게이트).
- 패자 동맹 해소: 도주 선두와 맺은 동맹은 자산이 아니라 위협이 되므로 스스로 파기합니다.
- 기회주의 배신: 동맹이 다른 세력에게 다굴당하는 중(들어오는 공격 병력이 동맹의 보유 병력 초과)이고 자신이 더 강하면 배신에 합류합니다 (어려움·불지옥 한정). 원작의 배신 규칙(최대 이득 동맹 배신, 유일 인접 약체 배신)과 별개 분기입니다.
- 동맹 끄기 설정에서는 전부 발동하지 않습니다.
- 구현: `packages/engine/src/execution/nation/NationAllianceBehavior.ts`의 `maybeContainmentDiplomacy` 등. `NationExecution`이 매 공격 틱에 호출하며, 동맹 체결·파기는 전황 대시보드 연대기에 기록됩니다.

## 개선 5 — 외교 상황판과 AI 외교 설명

개선 4에서 만든 AI 외교를 플레이어가 읽고 활용할 수 있게 합니다.

- `src/client/hud/layers/DiplomacyBoard.ts`: 싱글 게임 왼쪽 사이드바의 악수 버튼으로 여는 외교 상황판입니다.
  - 위협: 나를 공격 중인 세력과 총 병력, 도주 선두(패권 위협) 배너. 판정은 엔진 `findRunawayLeader`와 같은 규칙(난이도별 배수, FFA 한정)을 클라이언트에서 미러링합니다.
  - 동맹 관계: 살아있는 국가들의 모든 동맹 쌍과 남은 시간. 내 동맹은 강조합니다.
  - 국가 현황: 국가별 점유율·관계 상태(동맹/제안 보냄/제안 받음/교전 중/중립)·그 국가의 동맹 목록과 동맹 제안/파기 버튼. 기존 의도 파이프라인(`SendAllianceRequestIntentEvent` / `SendBreakAllianceIntentEvent`)을 그대로 쓰며, 동맹 끄기 설정에서는 숨깁니다.
- AI 행동 이유: `NationAllianceBehavior`가 판단 순간에 `GameUpdateType.DiplomacyNote` 업데이트(행위자·대상·위협·이유 코드)를 내보내고, 전황 대시보드 연대기가 동맹 체결/파기 항목에 그 이유를 덧붙입니다.
  - `accept_containment`(견제 연합 수락), `break_hegemon`(패권국 동맹 파기), `betray_opportunistic`(기회주의 배신)는 개선 4 분기입니다.
  - `betray_juiciest`·`betray_weak`·`betray_traitor`·`betray_lonely`는 원작 배신 분기의 이유 표기입니다.
  - 동맹 수락 판단은 `decideAlliance`가 어떤 분기가 결정했는지 함께 반환해, 견제가 실제 결정 사유일 때만 표기합니다.

## 개선 6 — 후방 방어 위임

플레이어가 후방 방어만 AI에 맡길 수 있습니다. 공격과 외교는 계속 직접 지휘합니다.

- `src/client/hud/layers/DelegationPanel.ts`: 싱글 게임 왼쪽 사이드바의 방패 버튼으로 여는 위임 패널입니다. 켜기/끄기, 예비 금고 비율(25/50/75%, 기본 50%), 행동 기록(시간·시설·비용, 최신순 최대 50건)과 총 위임 지출을 보여줍니다.
- 의도 흐름: 패널이 `SetDefenseDelegationEvent`를 보내면 Transport가 `set_defense_delegation` 의도(enabled, reservePercent 0–90)로 전달하고, ExecutionManager가 `DefenseDelegationExecution`을 만듭니다. 최신 의도가 같은 플레이어의 기존 실행을 대체하고, 끄기 의도는 실행을 남기지 않습니다. 건설 사이 최소 간격은 50틱(5초)입니다.
  - 주의: GameImpl은 다른 execution의 init() 안에서 추가된 execution을 유실하므로, 제어/작업을 나누지 않고 단일 자기교체 실행으로 구현했습니다.
- `DefenseDelegationBehavior`(packages/engine/src/execution/nation/): 반응형 방어 포대(공격 전선 뒤) → 예방형 방어 포대(적대적이고 충분히 강한 이웃 국경) → SAM 커버(핵이 활성화된 게임에서 도시·공장·사일로·항만 보호) 순으로 한 번에 하나씩만 짓습니다. 배치 규칙은 국가 AI와 같은 코드(`DefensePostPlacement`로 추출 공유)를 쓰되, 위임은 보조 기능이므로 난이도 게이트는 적용하지 않습니다.
- 자원 한도: 위임을 켠 시점의 금고를 기준(anchor)으로 삼아, 그 기준의 예비 비율만큼은 항상 남을 때만 짓습니다. 연속 건설로 기준이 내려가지 않고, 공격이나 직접 지출로 잔고가 예비금 아래로 내려가면 지출을 멈췄다가 수입으로 회복되면 다시 짓습니다. 끄고 다시 켜면 기준이 그때의 금고로 재설정되고, 켜진 상태에서 비율만 바꾸면 같은 기준에서 다시 계산합니다. 패널에 실제 예비금 액수와 재설정 시점을 표시합니다.
- 범위 제한: 위임은 방어 포대와 SAM 발사대의 ConstructionExecution만 발행합니다. 공격·병력 이동·외교·핵·경제 시설(도시/공장/항만/사일로)은 지시하지 않습니다.
- 행동 기록: 건설 지시 순간 엔진이 `GameUpdateType.DelegationNote`(시설·타일·비용)를 내보내고, 위임 패널이 이를 누적해 시간(`formatRecordDuration`)과 비용과 함께 보여줍니다.
- 대기 상태 표시: 위임이 켜져 있어도 지출이 없을 수 있으므로, 패널이 현재 대기 이유를 사실에 근거해 표시합니다. 잔고에서 방어 포대 비용을 빼면 예비금 하한을 깨는 경우 "예비금 보호 보류"(status_hold), 들어오는 공격 병력이 내 병력의 35%(엔진의 UNDER_ATTACK_THREAT_RATIO) 이상이면 "공격 감지, 포대 준비"(status_threat), 그 외에는 "위협 감시 중"(status_watch)입니다. 비용은 `me.buildables()`로 주기적으로(50틱) 다시 읽어 포대 누적에 따른 인상을 반영하고, 실제 배치 가능 여부 판정은 엔진만 하므로 배치 탐색 중에는 status_threat가 유지될 수 있습니다.
- 테스트: `tests/DefenseDelegation.test.ts`가 엔진 틱 루프에서 반응형 건설·50틱 간격·예비금 하한·고정 기준(연속 건설·건설비 상승 시 잔고 보호)·하한 아래 수동 지출 후 보류/수입 회복 후 재개·비율 변경 시 기준 유지와 끄기/켜기 재설정·무위협 대기·SAM 상한(도시당 0.25)을 검증합니다.

## 개선 7 — 일시정지 작전 계획

일시정지는 원래 의도를 모두 버리는 구간이었습니다(LocalServer가 pause 중 비-pause 의도를 폐기). 이제는 멈춰 있는 동안 공격을 예약해 두고, 재개할 때 순서대로 실행합니다.

- `src/client/WarPlan.ts`: 예약 큐의 순수 로직. 작전은 대상(국가 또는 중립지, 수송선 공격은 목적지 타일)과 병력 비율(1–100%)을 저장하고, 같은 대상의 중복 예약도 연속 파상공격으로 의미가 있으므로 그대로 둡니다. 순서 변경·삭제·비율 조정(5% 단위)을 지원합니다.
- 의도 가로채기: 기본 공격 경로(`ClientGameRunner.inputEvent`의 지상 공격과 `sendBoatAttackIntent`)와 레이디얼 메뉴 경로(`PlayerActionHandler.handleAttack`/`handleBoatAttack`) 모두 `uiState.paused`이 `uiState.paused`(GameRenderer가 `PauseGameIntentEvent`로 유지)이고 싱글 플레이·리플레이 아님·스폰 이후일 때, 의도를 보내는 대신 `QueuePlanOrderEvent`로 큐에 넣습니다. 멀티플레이·리플레이에서는 기존 동작 그대로입니다.
- `src/client/hud/layers/WarPlanPanel.ts`: 사이드바의 조준경 버튼(대기 작전 수 배지)으로 여는 작전판. 일시정지 버튼/단축키로 명시적으로 멈출 때도 자동으로 열립니다(설정 모달의 자동 일시정지는 열지 않음). 각 행에서 비율 −/+·순서 ↑↓·삭제, 하단에 완료 항목 정리와 전체 삭제가 있습니다.
- 실행: 재개(`PauseGameIntentEvent(false)`, 어떤 경로로 풀든)하면 200ms 틱마다 한 작전씩 위에서부터 발송합니다. 병력 수는 저장하지 않고 발송 시점의 생병력 × 비율로 다시 계산해, 앞 작전이 쓴 병력을 뒤 작전이 중복 사용하지 않습니다(엔진도 `min(보유, 요청)`으로 상한을 다시 칩니다).
- 무효 처리: 발송 직전에 대상 소멸·동맹 전환·병력 부족(<1)·수송선 출발 해안 없음을 검사해 이유를 표시하고 건너뜁니다. 엔진의 우호 대상 거부와 이중 방어가 됩니다.
- 세션 격리: 큐는 패널 컴포넌트 상태이고 새 게임의 `init()`에서 항상 초기화되며, localStorage에 저장하지 않습니다. 사망·게임 종료 시 실행을 멈춥니다.
- 일시정지 중 재개하지 않고 닫아도 큐는 유지되며, 다음 재개 때 이어서 실행됩니다. 실행 중 다시 멈추면 남은 작전은 다음 재개까지 대기합니다.
- 테스트: `tests/WarPlan.test.ts`가 큐 동작(중복 허용·순서 변경 경계·비율 클램프·병력 계산·상태 전이)을 검증합니다.

## 개선 8 — 지도 위 외교·위협 표시

외교 상황판(개선 5)의 정보를 지도 위에서 바로 읽을 수 있게 합니다.

- `src/client/DiplomacyMarkers.ts`: 마커 계산 순수 로직. 국가당 마커 하나, 우선순위는 공격자 > 패권 위협 > 동맹(나를 공격 중이면 배신 진행 중이라도 적색이 우선). 도주 선두 판정은 외교 상황판과 같은 규칙(엔진 `runawayLeadFactor` 미러, FFA 한정)을 씁니다.
- `src/client/hud/layers/DiplomacyMapOverlay.ts`: 캔버스 오버레이(z-30, pointer-events 없음). 내 동맹 수도에 녹색 이중 링+🤝, 나를 공격 중인 세력 수도에 적색 펄스 링+⚔+병력 수, 도주 선두에 황색 펄스 다이아몬드+⚠를 그립니다. 공격받는 지역은 `attackClusteredPositions`를 400ms 간격(in-flight 가드)으로 폴링해 전선 클러스터에 붉은 펄스 영역으로 표시합니다(AttackingTroopsController와 같은 필터: 국가가 아닌 부족 공격 제외). 마커 데이터는 200ms 틱으로 갱신하고 그리기는 매 프레임(rAF) 실행해 카메라 이동·확대에 붙어다닙니다. 싱글 전용이며 스폰 단계·리플레이·내 소멸 후·대체 보기에서는 숨깁니다.
- 토글: 왼쪽 사이드바 깃발 버튼(공격자 수 배지). 상태는 `settings.diplomacyMapOverlay`(기본 켜짐)에 저장되고, 다른 패널과 달리 서로를 닫지 않습니다.
- 외교 상황판 연결: 위협 행을 누르면 해당 공격의 전선 위치(없으면 공격자 수도)로, 헤게몬 배너·국가 행·내 동맹 행을 누르면 그 국가 수도로 카메라가 이동합니다(`GoToPositionEvent`/`GoToPlayerEvent`). 이동과 함께 상황판은 닫혀 바로 대응할 수 있습니다.
- 테스트: `tests/DiplomacyMarkers.test.ts`가 집계(후퇴 제외)·도주 선두 판정(난이도 배수·FFA 한정·봇 제외)·우선순위와 제외 규칙을 검증합니다.

## 개선 10 — 작전 계획 지도 시각화

일시정지 작전 계획(개선 7)의 예약이 지도 위에서 바로 읽히게 합니다. (개선 9는 위임 세부 설정 — 시설별 토글·건설 우선순위·보호 구역 지정 — 으로 코드 주석에 문서화되어 있습니다.)

- `src/client/WarPlan.ts`: `WarPlanMarker`와 `WarPlanMarkersEvent` 추가. 마커의 번호(`row`)는 작전판 목록의 행 번호와 같아서, 지도의 숫자와 목록의 숫자가 항상 일치합니다. 완료(실행·건너뜀)된 작전은 마커에서 빠지되 행 번호는 유지됩니다. `queuedPlanRows`가 이 대응을 순수 함수로 제공합니다.
- 위치 결정: 지상 공격은 클릭한 타일(`ClientGameRunner`와 레이디얼 메뉴 경로 모두 `QueuePlanOrderEvent`에 클릭 타일을 싣습니다)에, 타일 정보가 없는 예전 경로는 대상 국가의 이름 위치(nameLocation)에, 수송선 작전은 목적지 타일에 놓습니다.
- `src/client/hud/layers/WarPlanMapLayer.ts`: 캔버스 오버레이(z-28, pointer-events 없음). 대기 중인 각 작전에 황색 번호 배지(지상=원, 수송선=마름모)를 그리고, 실행 순서대로 점선 경로를 이어 공격 순서와 방향이 보이게 합니다. 일시정지 여부와 무관하게 대기 작전이 있는 동안 표시되므로 실행 중에도 남은 큐를 따라다닙니다. 싱글 전용, 스폰 단계·리플레이·내 소멸 후·대체 보기에서는 숨깁니다.
- 목록 → 지도 연결: 작전판의 행을 누르면 카메라가 그 위치로 이동(`GoToPositionEvent`)하고 패널은 닫히며, 해당 배지가 잠시 펄스로 강조됩니다. 행 안의 비율·순서·삭제 버튼은 이벤트 전파를 막아 기존 동작 그대로입니다.
- 큐 동작 불변: 마커 갱신은 기존 변경 지점(추가·순서·삭제·비율·실행·건너뜀·정리)에서만 방송하고, 큐의 저장 구조와 실행 규칙은 바꾸지 않습니다.
- 테스트: `tests/WarPlan.test.ts`에 클릭 타일 보존, 재정렬·삭제 후 행 번호 재계산, 완료 항목 제외와 번호 유지를 추가했습니다.

## 네트워크 차단 (soloStatic)

정적 배포에서는 외부 서버가 없으므로, 서버 의존 경로를 소스에서 차단합니다. `ClientEnv.soloStatic()`(PAGES_BASE 설정 빌드에서 참)을 게이트로 씁니다.

- `ServerList.ensureServerList` / 폴링: 서버 목록 fetch 없이 로컬 구성만 적용
- `Api.getNews`: 번들 뉴스 즉시 반환
- `Main`: 광고(Admiral) 페이로드 비활성
- `Cosmetics`: 코스메틱 fetch 건너뜀
- `WinModal.innerHtml`: 스토어/프로모 iframe 생성 차단
- `UsernameInput`: 인증 이름 UI 제거, 기기 로컬 이름만
- `Utils.homeHref`: 서브패스 기준 홈 링크

검증은 `performance.getEntriesByType("resource")` 전수 감사로 부팅→게임→종료→메뉴 재진입 전 구간 외부 요청 0건을 확인합니다.

## 검증 현황과 한계

- 단위 테스트: 기록 검증, 챌린지 게이트, 견제·기회주의 외교 등 31건 (`tests/RecordsRevalidate.test.ts`, `tests/ChallengesGate.test.ts`, `tests/NationContainment.test.ts`, `tests/NationOpportunisticBetrayal.test.ts`).
- 통제 통합 테스트: `tests/NationContainmentIntegration.test.ts`가 배포와 같은 엔진 배선(`NationExecution` → `executeNextTick`)으로 도주 선두 트리거를 결정적으로 재현합니다. 견제 연합 성립, 패자 동맹 파기, 연대기가 소비하는 업데이트(AllianceRequestReply·BrokeAlliance) 방출을 확인합니다.
- 자연 플레이 관찰 (유럽·어려움, 사망 후 관전): AI 간 동맹 89건 자연 체결, 연대기 이유 문구 실측 — "Ukraine → Romanian Lordship 동맹 파기 — 압도적 열세 동맹 배신". 플레이어 동맹 제안 → AI 수락 → 파기(배신자 플래그) 전 사이클을 실입력으로 확인. 도주 선두 견제 연합의 자연 발동 장면은 아직 미관찰(관찰 종료 시 선두 비율 1.04배)이므로, 견제는 통제 통합 테스트 증거와 구분해서 평가합니다.
- 후속 수정: 언어 JSON fetch에 `cache:"no-cache"`(무해시 URL이라 구 캐시가 남아 신규 문자열이 영어로 폴백하던 문제), 외교판 국가 목록을 멤버십 변경 시에만 재정렬(200ms 틱 재정렬로 버튼이 커서 아래에서 움직이던 문제). 데스크톱·모바일(390px) 실기기 렌더링 검증 완료.
- 알려진 잔여 리스크: 기록 재검증이 백업 없이 삭제하던 이전 배포에 노출된 기기에서 기록 로테이션(200건 초과)까지 진행된 경우, 그때 삭제된 업적은 복구할 수 없습니다.
